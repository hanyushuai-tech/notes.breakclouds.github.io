LLM Wiki 使用指南

灵感来自 Andrej Karpathy 的 LLM Wiki 模式。由 LLM 替你维护一个结构化、互联互通、持续演进的知识库。

一、这是什么？

传统的知识管理方式是这样：你收藏一堆文章、论文、笔记，然后某天想找个东西，在文件夹里翻半天，或者用 RAG 工具临时检索。每次提问，AI 都要从零开始拼凑答案。知识没有积累。

LLM Wiki 的做法完全不同：

你负责：收集资料、提出问题、判断方向
LLM 负责：总结、交叉引用、归档、维护一致性

每次你添加一份新资料，LLM 不是简单地索引它，而是把它消化吸收进已有的知识体系中——更新实体页面、修订概念页面、标记新旧矛盾、强化或质疑现有论断。Wiki 是持续复合增长的。

用一句话描述：Obsidian 是你的 IDE，Claude 是你的程序员，Wiki 是你的代码库。

二、目录结构总览

你的仓库/
├── CLAUDE.md              # 🔧 核心配置：告诉 LLM 如何维护 Wiki
├── LLM-Wiki使用指南.md     # 📖 本文件
│
├── raw/                   # 📥 原始资料（只读，LLM 不修改）
│   ├── assets/            #    图片附件
│   └── 你收集的文章.md
│
├── wiki/                  # 📚 LLM 维护的知识库
│   ├── index.md           #    全库目录（按分类列出所有页面）
│   ├── log.md             #    操作日志（按时间记录所有操作）
│   ├── overview.md        #    知识总览（"当前最佳理解"）
│   ├── entities/          #    实体页面（人物、组织、产品…）
│   ├── concepts/          #    概念页面（理论、方法、框架…）
│   └── sources/           #    来源摘要（每份资料对应一页）
│
└── (你原有的笔记...)       # 你仍可以在仓库里写自己的笔记

三、三种核心操作

操作 1：摄入（Ingest）—— 让新知识入库

场景：你刚用 Obsidian Web Clipper 剪藏了一篇好文章，存到了 raw/ 目录下。

你对 Claude 说：

“摄入 raw 下的《XXX》文章”

Claude 会做什么：

  1. 阅读原始资料
  2. 用 3-5 句话告诉你关键收获，和你讨论重点
  3. 在 wiki/sources/ 创建来源摘要
  4. 更新/新建相关的实体页面和概念页面
  5. 更新 wiki/index.md 目录
  6. 在 wiki/log.md 追加操作记录
  7. 如果有重大发现，更新 wiki/overview.md

一次摄入可能触及 10-15 个页面——这正是 LLM 的强项。人类不可能有这个耐心。

你也可以：

  • 直接给一个链接：“摄入这篇文章：https://…”
  • 粘贴一段文字：“把这段话消化进 Wiki”
  • 批量摄入：“把 raw 目录下所有新文件都处理了”

操作 2：问答（Query）—— 基于已有知识回答

场景：你想了解 Wiki 中某个主题的当前理解。

你对 Claude 说：

“关于 XXX，我们目前知道什么？” “对比一下 A 和 B 两个概念” “给我做一个关于 XXX 的 Marp 演示文稿”

Claude 会做什么：

  1. 读取 wiki/index.md 找到相关页面
  2. 深入阅读后综合所有信息
  3. 给出带 引用链接 的回答
  4. 如果回答有长期价值，主动问你是否归档回 Wiki

关键理念：好的回答不应该消失在聊天记录里。你问过的好问题、Claude 给出的好分析，都应该归档回 Wiki，让探索也变成知识积累。

操作 3：巡检（Lint）—— 保持知识库健康

场景：Wiki 已经积累了几十上百个页面，你想确保质量。

你对 Claude 说：

“巡检一下 Wiki” “检查有没有矛盾的地方” “有没有孤立页面”

Claude 会检查：

  • 🔴 矛盾：不同页面之间是否有互相矛盾的论断
  • 🟡 过时：是否有被新资料推翻的旧内容
  • 🟠 孤立页面：有没有入链为 0 的页面
  • 🟢 缺失页面：反复出现的重要概念是否缺少独立页面
  • 🔵 缺失交叉引用：相关内容是否没链接上
  • 🟣 信息缺口：有哪些值得深挖但资料不足的方向

建议每周巡检一次，或者在连续摄入 5-10 份资料后来一次。

四、快速上手：三步开始

第一步：准备资料

用 Obsidian Web Clipper 浏览器插件把感兴趣的文章剪藏为 Markdown，存到 raw/ 目录。

💡 建议在 Obsidian 设置中绑定「下载附件到本地」的快捷键，这样图片不会因链接失效而丢失。 设置 → 文件和链接 → 附件文件夹路径 → raw/assets/ 设置 → 快捷键 → 搜索”下载”→ 绑定 Ctrl+Shift+D

第二步：让 Claude 摄入

打开 Claude Code（在 Obsidian 仓库目录下），说：

“摄入 raw/ 下的文章”

Claude 会读取、总结、和你讨论，然后把知识写入 Wiki。

第三步：浏览成果

在 Obsidian 中打开 wiki/overview.md，看一看当前的知识全景。点击 wiki/index.md，浏览所有页面。打开图谱视图（Graph View），感受知识网络的生长。

五、进阶用法

图谱视图

Obsidian 图谱视图是了解 Wiki 形态的最佳方式。你能看到：

  • 哪些页面是枢纽（链接最多）
  • 哪些页面是孤岛（没有链接）
  • 知识簇是如何形成的

搜索

  • 小规模（< 100 个页面）：index.md 足够用
  • 中等规模（100-500 页）：结合 Obsidian 内置搜索
  • 大规模（500+ 页）：可以考虑引入 qmd 等本地搜索引擎（BM25 + 向量 + LLM 重排）

Marp 幻灯片

Obsidian 有 Marp 插件。你可以让 Claude 直接从 Wiki 内容生成演示文稿：

“用 Wiki 中关于 XXX 的内容，做一份 Marp 幻灯片”

版本控制

整个 Wiki 是纯 Markdown 文件，天然支持 Git。你可以：

  • git init 初始化仓库
  • 每次摄入后提交，记录知识演化的完整历史
  • 回退到任意历史版本

六、适合什么场景？

场景示例
个人成长追踪目标、健康、心理，归档日记和文章，建立自我认知地图
深度研究数周数月钻研一个话题，读论文、文章、报告，构建综合性 Wiki
读书笔记逐章消化一本书，建立人物、主题、情节的 Wiki 页面
学习笔记课程笔记、概念整理、知识点交叉引用
竞品分析持续跟踪竞争对手，消化新闻、财报、产品更新
团队知识库Slack 讨论、会议记录、项目文档自动归档

七、核心哲学

维护知识库最痛苦的从来不是「阅读」和「思考」，而是繁琐的簿记工作：更新交叉引用、保持摘要时效、标记新旧矛盾、在几十个页面间保持一致性。人类放弃 Wiki，是因为维护成本增长得比价值更快。

LLM 不会厌倦，不会忘记更新交叉引用，一次能触及 15 个文件。Wiki 得以持续维护，因为维护成本趋近于零。

你的工作是：策展资料、引导分析、提出好问题、思考这一切的意义。LLM 的工作是：所有其他事情。

八、让系统和你一起成长

CLAUDE.md 不是写死的。当你和 Claude 在协作中发现更好的工作方式——

  • 说「更新规范，以后实体页面应该多一个 XXX 字段」
  • 说「我觉得 concept 和 entity 之间应该再区分一下」
  • 说「以后巡检的时候顺便检查 XXX」

你和 Claude 共同演化这套规范，让它越来越贴合你的使用习惯。

开始你的第一份摄入吧。
